# 跨域植物病害识别怎样评估：从域定义到留一域测试

> 本文整理公开的跨域评估方法，不披露审稿中工作的模型结构、训练配置或实验结果，也不声称某种方法在所有作物上普遍有效。

在实验室背景上训练的植物病害分类器，到了田间可能突然失效。变化的不只是“图片风格”：作物品种、病程、相机、拍摄距离、季节、地域和背景都会改变输入分布。若把这些变化全部压缩成一个模糊的“跨域”，模型即使失败，我们也很难知道失败发生在哪里。

因此，跨域研究的第一步不是选择损失函数，而是定义域。

![跨域植物病害识别的留一域评估流程](https://carter6713.github.io/blog/img/research-notes/cross-domain-evaluation.png)

## 一、域不是由数据集名称自动决定的

同一个公开数据集可能包含多个设备、地点或采集批次；两个名称不同的数据集也可能共享图片来源。一个可用的域定义应同时回答：

- 哪个因素发生了变化？
- 这个因素在训练时是否可见？
- 目标域的标签在模型选择阶段是否可用？
- 域标签来自采集元数据，还是事后根据图像外观推断？

对植物病害图像，可以把域拆成四条轴：

| 域轴 | 例子 | 可能的捷径 |
|---|---|---|
| 作物与品种 | 番茄、苹果、柑橘 | 叶形和纹理替代病灶特征 |
| 采集设备 | 相机、手机、扫描仪 | 分辨率、锐化和压缩噪声 |
| 场景背景 | 纯色背景、温室、田间 | 背景颜色和构图 |
| 时间与地点 | 季节、试验站、地域 | 光照、病程和管理方式 |

如果只写“训练集 A、测试集 B”，读者无法判断模型是在跨作物、跨设备还是跨场景。

## 二、区分域适应和领域泛化

两种设置经常被混在一起：

- **无监督域适应**：训练时能够看到目标域的无标签样本；
- **领域泛化**：训练时看不到目标域样本，模型直接在未知域上测试。

二者都研究分布偏移，但信息边界不同。如果训练流程读取了目标域图像来做归一化、提示词选择或早停，即使没有读取标签，也不能再称为纯粹的领域泛化。

## 三、留一域测试的基本结构

假设有四个域 A、B、C、D。一次实验可以用 A、B、C 训练，并把 D 完整留作目标域。随后轮换目标域：

```text
Run 1: train A+B+C -> test D
Run 2: train A+B+D -> test C
Run 3: train A+C+D -> test B
Run 4: train B+C+D -> test A
```

这比把所有图片随机混合后划分更接近“遇到一个新环境”的问题。但模型选择仍是难点：若用目标域 D 的标签选超参数，D 就不再未知。

一种可解释的策略是在源域内部再留出一个验证域，或使用源域交叉验证。无论采用哪种策略，都应把它写进实验协议，而不是只报告最终测试设置。

## 四、不要只报告一个平均准确率

类别不均衡与域大小差异会让总体准确率掩盖失败。至少可以同时报告：

1. 每个目标域的 Macro-F1；
2. 所有目标域的平均值；
3. 最差目标域表现；
4. 每类召回率与混淆矩阵；
5. 概率校准指标，如 ECE 或 Brier score；
6. 多个随机种子或划分下的波动。

其中“最差域”很重要。一个模型在三个相似域上表现很好、在真正困难的田间域上彻底失败，平均值可能仍然好看。部署关心的却往往正是最困难的那个域。

## 五、基线必须足够朴素

领域泛化论文容易把注意力集中在复杂模块上，但 DomainBed 的经验提醒我们：模型选择与实现细节足以显著改变比较结果。因此建议先建立清晰的基线阶梯：

```text
ImageNet 预训练 + ERM
        ↓
统一增强与训练预算
        ↓
通用领域泛化基线
        ↓
待研究方法
```

所有方法应共享骨干网络、输入分辨率、优化预算、早停规则和超参数搜索范围。若某个方法使用了更多外部数据、更大的模型或目标域无标签图像，应单独说明，而不能把差异全部归因于算法。

## 六、生成式增强需要额外的域边界

生成式数据增强在跨域任务中有两种相反风险：

- 生成样本过度复制源域风格，增加数量却没有扩大有效分布；
- 生成器预训练数据可能包含与目标测试集相近甚至重叠的内容。

因此，除了图像质量，还应检查合成样本带来的域覆盖变化：病灶是否仍可辨认、背景是否成为新的捷径、不同目标域是否一致受益。只在一个域上提高，并不能自动证明跨域泛化增强。

## 七、可解释性用于定位域捷径

显著性图或注意力图不能单独证明模型“理解了病害”，但可以用于比较不同域的关注区域。如果模型在实验室图像中关注病斑，在田间图像中转向天空、标签牌或叶片边缘，就为失败分析提供了线索。

更可靠的做法是把可解释性观察与遮挡实验、背景替换、病灶区域评估结合起来。目标不是挑选几张漂亮的热力图，而是提出可被反驳的假设：模型是否依赖某个随域变化的捷径？

## 九、上线前再问三个问题

1. 新场景的变化是否被测试域覆盖？
2. 低置信度样本能否被拒绝或交给人工复核？
3. 新域数据进入系统后，是直接继续训练，还是先经过独立审计？

跨域评估的价值，不是制造一个更难的排行榜，而是让“模型能否离开当前数据集”成为可回答的问题。域定义越清楚，失败越容易解释，改进也越有方向。
